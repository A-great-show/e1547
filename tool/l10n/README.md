# 简体中文汉化补丁

本目录存放 e1547 的简体中文汉化方案。上游项目没有任何 i18n 框架，所有界面文字都硬编码在
Dart 源码里，因此这里采用**构建期打补丁**的方式：

1. `zh_cn.json` 是词典：`英文原文 -> 中文`，键名必须和源码中**引号内的内容逐字符一致**。
2. `apply_zh.py` 在 `flutter build` 之前扫描 `lib/**/*.dart`，把命中的字符串字面量替换成中文。
3. `.github/workflows/build-zh-apk.yml` 自动完成「打补丁 → 编译 → 发布 APK」。

这样 fork 的源码和上游保持一致，`git pull upstream master` 不会因为汉化产生冲突，翻译的增删改
都只是词典里的一行 diff。

## 安全策略

脚本刻意做得很保守，只替换「一个 token 的普通字符串字面量」，并跳过：

- 生成文件：`*.g.dart`、`*.freezed.dart`、`*.drift.dart`
- 注释
- 含 `${...}` 插值的字符串
- 后面紧跟 `:` 的字面量（Map 的 key）
- 所在行涉及路由、请求参数、Header、存储 key 等的字面量

## 本地调试

```bash
# 只看会改哪些地方，不写入文件
python3 tool/l10n/apply_zh.py --dry-run
```

输出末尾会列出「词典里有、但源码里找不到」的条目，说明上游改了文案或者键名写错了，需要同步修正。

## 如何补充翻译

1. 在源码里找到硬编码的英文，例如 `Text('Comments')`。
2. 在 `zh_cn.json` 的 `strings` 里加一条 `"Comments": "评论"`。
3. 推送到 `zh-cn` 分支，Actions 会自动重新打包。

## 已知的未覆盖部分

- 带 `${...}` 插值的句子（例如 `'${count} tags blocked'`）需要逐条手工改源码，后续按页面处理。
- 由枚举 getter 生成的文案（例如主题名、视频分辨率名）不在字符串字面量里，需要单独翻译。
- 来自服务端的内容（帖子标题、标签、评论）本身不属于汉化范围。
